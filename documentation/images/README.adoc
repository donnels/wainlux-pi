= Images Directory Structure
:imagesdir: .

This directory contains all diagrams, screenshots, and images used in the project documentation.

== File Naming Convention

Files are organized by TOGAF phase using the following prefix scheme:

.Naming Prefixes (4-8 characters)
[cols="1,1,2,4",options="header"]
|===
| Prefix | Phase | Category | Description
| `arch-` | Architecture | Architecture | System context, component, deployment, and decision diagrams
| `app-` | Application | Application | Software components and service diagrams
| `biz-` | Business | Business | Workflows and process diagrams
| `test-` | Testing | Test | Test scenarios, sequences, and validation diagrams
| `prot-` | Technology | Protocol | K6 protocol documentation (EDN + SVG)
| `hw-` | Technology | Hardware | Physical component photos
| `capt-` | Capture | Capture | Screenshots and photo evidence
| `style-` | N/A | Style | Configuration files (e.g., PlantUML styles)
|===

== Diagram Generation

=== PlantUML Diagrams

All `*.plantuml` files use the shared `style-plantuml.puml` for consistent styling.

 Render all PlantUML diagrams to PNG:
[source,bash]
----
cd documentation/images
# Use podman/flatpak as shown in scripts/generate_diagrams.sh
flatpak-spawn --host podman run --rm --user root -v "$(pwd):/repo" \
  docker.io/plantuml/plantuml:latest /repo/<FILE>.plantuml
----

=== Bytefield-SVG Diagrams

Protocol diagrams (`prot-*.edn` -> `prot-*.svg`) are generated using Bytefield-SVG in the `docker/docker-bytefield/` container.

== Security Notes

* `capt-recovery-qr.png` contains synthetic instructions and codes, not current Pi rasters
* `test-recovery.plantuml` describes Pi-reviewed card submission and recovery workflow
* No real credentials, SSIDs, or IP addresses are embedded in any diagrams
* All hardware photos show proposed/referenced devices, not installed/tested equipment
