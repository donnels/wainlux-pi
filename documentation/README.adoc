Current documentation for the Rust K6 service on Pi Zero W. Superseded implementation history is omitted here; retained protocol observations are evidence, not descriptions of the current application.

The current HTTP API contract is link:../docker/docker-wainlux-rs/README.adoc[documented with the service] and served by `GET /api`. Its OpenAPI 3.1 spec is served at `GET /openapi.yaml`; bundled Swagger UI is at `GET /docs`. Contract tests live in `app/tests/api.rs`.

== Card Placement and Reuse

The drawings use the current measured card, K6 working reach and template geometry. The QR symbol is a generic placeholder; exact private pixels are shown only in the live app preview.

.Card-local item coordinates are translated to the bed
image::card-items.svg[Generic QR and optional text placement,align="center"]

.First burn the U markings on bare backing; leave the card out
image::card-guide.svg[U markings on bare backing without the card,align="center"]

.Rust operator UI preview using synthetic input in simulator mode; no burn started
image::ui-simulator-preview.png[Simulator card and raster preview,align="center"]

For a new backing, place the bare backing and start the optional markings stage first. Confirm the machine has stopped, then place the card against those marks. Edit the card fields and positions in the UI; the card drawing and laser raster preview reflect the current values. Review the exact raster before starting the content stage. A repeat card can reuse the same markings without burning them again. For a second side, inspect the first side, confirm rest, flip the card into the same guide, confirm placement and start that stage separately.
