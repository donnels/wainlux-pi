Current documentation for the Rust K6 service on Pi Zero W. Protocol observations are evidence, not descriptions of vendor code.

The service README documents the HTTP API, served at `GET /api`. OpenAPI 3.1 is at `GET /openapi.yaml`; Swagger UI is at `GET /docs`.

The canonical build and test command is `./scripts/build_laser.sh` from the repository root.

== Card Placement and Reuse

The drawings use the current measured card, K6 working reach and template geometry. The QR symbol is a generic placeholder; exact private pixels are shown only in the live app preview.

.Choose a card placement before placing content
image::card-placement.svg[Centered and left-aligned card placement,align="center"]

.Card-local item coordinates are translated to the bed
image::card-items.svg[Generic QR and optional text placement,align="center"]

.First burn the U markings on bare backing; leave the card out
image::card-guide.svg[U markings on bare backing without the card,align="center"]

.Rust operator UI preview using synthetic input in simulator mode; no burn started
image::ui-simulator-preview.png[Simulator card and raster preview,align="center"]

For a new backing, place the bare backing and start the optional markings stage first. Confirm physical rest, inspect the markings and explicitly accept or record a deviation. Only then place the card against those marks and acknowledge placement. Edit content in the primary form and positions under Layout and sizing; Review output requests the Pi's exact raster. A repeat card can reuse the same markings without burning them again. For a second side, inspect and accept the first side, confirm rest, flip the card into the same guide, confirm placement and start that stage separately. No verdict starts the next stage.
