This reference describes packet layouts generated or consumed by the current Rust `k6` driver and the device behavior observed while testing it. It is not a description of a vendor application's internals. The driver supports raster work; vectors and firmware updates are not part of this interface.

== Link and Coordinates

* Serial device: normally `/dev/ttyUSB0`; baud: 115200.
* Pixel pitch: 0.05 mm (20 pixels/mm).
* Current normal K6 working reach: 80 x 75 mm. The Y value is an operator-selected bound, not an exact measurement of the mechanical stop.
* The firmware-coordinate envelope is 1600 x 1600 pixels. Normal jobs are constrained by the smaller working profile.
* Raster rows are packed MSB-first; each row is padded to a whole byte. Black pixels are set bits.
* For a raster with top-left `(x, y)`, the header center is `center_x = x + width/2 + 67`, `center_y = y + height/2`.

== Response Bytes

[cols="1,3",options="header"]
|===
| Bytes | Observed meaning
| `09` | ACK for commands/chunks that the driver expects to acknowledge.
| `08` | Error response; observed when a DATA payload is entirely zero.
| `FF FF FF FE` | Device activity/heartbeat frame, including after a job header.
| `FF FF 00 xx` | Progress frame; `xx` is the reported percentage byte.
|===

The Rust driver accepts `FF FF 00 64` (100) as reported completion. If no byte arrives for 90 seconds, it reports assumed completion and may proceed to the next band. Silence is not device confirmation or proof of physical rest.

== Commands Used by the Driver

[cols="1,3,3",options="header"]
|===
| Name | Packet | Driver behavior
| STOP | `16 00 04 00` | Writes the stop frame. During an active burn this is also sent through the stop handle while cancellation is latched. It does not by itself prove motion stopped.
| VERSION | `FF 00 04 00` | After STOP and input drain, reads three version bytes. Observed firmware: `04 01 06`.
| CONNECT | `0A 00 04 00` | Sent twice; each command expects `09`.
| HOME | `17 00 04 00` | Expects `09`.
| BOUNDS | `20 00 0B` + width, height, center X and center Y as four big-endian `u16` values | Laser-off frame request; expects `09`.
| FRAMING | `21 00 04 00` | Expects `09`; ends the frame mode in the observed workflow.
| JOB_HEADER | 38-byte `0x23` packet described below | The driver waits for an activity/status frame; this packet has no ACK contract in the driver.
| DATA | `0x22` packet described below | Up to 1900 payload bytes. Each chunk expects `09`; timeout/error can retry that chunk up to three attempts with backoff.
| INIT | `24 00 0B 00 00 00 00 00 00 00 00` | Sent twice after DATA with approximately 200 ms, then 500 ms spacing before status monitoring.
|===

A normal burn band sends FRAMING, JOB_HEADER, a size-dependent delay, two CONNECT commands and the DATA chunks, followed by two INIT commands. The driver then monitors status frames. A multi-band raster repeats the band sequence for each nonblank band.

A normal machine stop also sends STOP, then FRAMING and HOME. An in-burn stop may only reach the immediate stop handle and cancellation path. The operator must confirm physical rest before changing placement or continuing.

== JOB_HEADER (0x23)

.K6 raster JOB_HEADER layout; vector-reserved bytes are zero in the Rust driver
image::k6-prot-tx-23-job-header.svg[JOB_HEADER packet layout,align="center"]

All multibyte fields are big-endian. The current raster-only builder sets:

[cols="1,2,3",options="header"]
|===
| Bytes | Field | Current value
| 0-2 | Opcode, reserved, length | `23 00 26` (38 bytes)
| 3-4 | Packet count | `(total_size / 4094) + 1`, integer division
| 5 | Mode | `01`
| 6-7 | Raster width | Pixels, `u16`
| 8-9 | Raster height | Pixels, `u16`
| 10-11 | Raster data offset | `00 21` (33)
| 12-13 | Power | `u16`, machine setting
| 14-15 | Depth | `u16`, machine setting
| 16-19 | Vector width/height slots | Zero
| 20-23 | Total size | Raster bytes + 33, `u32`
| 24-31 | Vector power/depth/count slots | Zero
| 32-33 | Center X | `u16`, pixels
| 34-35 | Center Y | `u16`, pixels
| 36 | Repeat | `01`
| 37 | Reserved | `00`
|===

The 33-byte data offset, raster-only values and repeat value describe the current Rust packet builder. Do not infer vector support from the reserved fields.

== DATA (0x22)

.K6 raster DATA layout
image::k6-prot-tx-22-data.svg[DATA packet layout,align="center"]

* Bytes 0-2: opcode `22` and total packet length as a big-endian `u16`.
* Bytes 3 through the byte before the end: up to 1900 bytes of packed raster payload.
* Final byte: two's-complement checksum. The sum of the complete packet is zero modulo 256.

The driver drops blank edge rows and splits at long blank runs so that no transmitted 1900-byte chunk is all zero. This is a workaround for the observed `08` response to an all-zero DATA payload. It can result in several independent bands for one reviewed raster; progress percentages are band-local.
