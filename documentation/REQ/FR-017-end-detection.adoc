= FR-017: Physical End Estimates

== Status
Partially implemented. Bounded per-job receive traces and recording synchronization are available for power-sweep attempts. No validated physical end estimator exists.

== Requirement
Report evidence about when laser motion or marking may have ended without claiming that a protocol response, timeout, or acoustic quiet proves physical rest. Preserve the distinction between device-reported completion and assumed completion. Use synchronized external observations to evaluate candidate end estimates before changing automatic job sequencing.

== Acceptance

* The K6 driver can capture a bounded, receive-only trace per job, including monotonic event time, job index, raw received bytes, decoded status/heartbeat frames, progress and quiet intervals. The trace reports its byte/event limits and whether it was truncated.
* Trace capture records no outgoing DATA/raster bytes or submitted user content and does not change the completion policy.
* A Real-mode UI run can play a preamble plus a six-digit DTMF recording ID derived from the planned attempt ID. The audit log records the attempt ID, recording ID, nominal cue duration/lead and marker time; this metadata does not prove a microphone captured the cue.
* A containerized analysis tool accepts an audio recording read-only, decodes the DTMF ID only to associate the recording with its attempt, and reports filtered run-log events and measured processing timings. It does not classify audible activity or infer head motion, laser state or physical completion from sound.
* Pi-local capture associates audio with the attempt through a capture-relative monotonic time origin, without requiring an audible cue. Filtered run events and recordings are analyzed off-Pi, and the Pi UI presents processing state and the resulting report. An audible cue remains optional for phone or independent capture.
* Manual iPhone Voice Memos import remains available independently of any Pi microphone HAT. The upload is associated with a selected attempt and filtered run events; the audible recording ID is checked when present.
* A microphone HAT is not assumed compatible based only on its 40-pin connector. Validate the original Zero W's CPU/OS support, GPIO allocation, power use and capture performance before installation; do not add a USB microphone to the current OTG laser setup.
* A physical end estimate is not promoted to automatic progression until it has been correlated against attended observations over repeated runs and material/settings combinations. Ambiguous evidence requires operator judgment.
* Operator OK/deviation/comment remains the authoritative physical assessment for the current experiment.
