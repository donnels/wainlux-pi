= FR-002: WiFi QR Composition

== Status
Implemented in the `wifi-login` use case; physical acceptance is material and phone dependent.

== Requirement
Compose a WiFi payload as a QR and preview the resulting raster before a stage can run.

== Acceptance

* Accept SSID, password, security type and hidden-network flag through declared fields or the typed API.
* Encode credentials in the QR; never bind the password to printed text.
* Keep QR size and position within the selected material's etch area; reject overflow.
* Return preview pixels and dimensions before planning or running.
