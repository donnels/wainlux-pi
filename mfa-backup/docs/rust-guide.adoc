= Read The Rust Code

This CLI is also a teaching aid. Read the small application flow first.
Then follow one module at a time. Use synthetic codes while learning.
The refactor changes the structure, not the backup format or command-line options.

== What Goes Where

The project root is the folder containing `readme.adoc`.
It is the starting point for using the tool. This guide explains its implementation.

[cols="1,3",options="header"]
|===
|Location |Purpose
|`readme.adoc` |User instructions, security decisions, and links to the rest.
|`cli/src/` |Rust source code. The compiler turns it into an executable.
|`cli/Cargo.toml` and `cli/Cargo.lock` |Build metadata and dependency choices.
|`cli/assets/` |The embedded print font and its redistribution license.
|`docs/` |This guide, the workflow source, and its rendered image.
|`examples/` |A reusable instruction template, not real recovery codes.
|`private/` |The original recovery codes. Keep this folder private.
|`output/` |Backups generated when the tool runs. They contain secrets too.
|`cli/target/` |Cargo's build products: executables, test binaries, and cache files.
|===

`output/` and `cli/target/` may not exist until you create outputs or build locally.
They are not source folders. They can be regenerated from the retained inputs.
Do not delete your only working recovery backup just because it was generated.

== File Types

[cols="1,3",options="header"]
|===
|Type |Meaning Here
|`.rs` |Rust source. `main.rs` contains the entry point; the other files are modules.
Tests are Rust code too, kept inside their modules.
|`.toml` |Structured settings written in TOML. Cargo's manifest describes this
package and the libraries needed to build it. It is not executable Rust.
|`.lock` |Cargo's generated dependency lockfile. It records resolved versions and
checksums, including dependencies of dependencies. It does not lock the NFC card.
|`.adoc` |AsciiDoc: plain-text documentation with headings, links, and code blocks.
A renderer can turn it into HTML or PDF. The documentation itself is not the CLI.
|`.plantuml` |Text describing a diagram. PlantUML renders it into an image.
It documents the workflow; it does not perform the backup steps.
|`.txt` |Plain text. The template contains instructions; files in `private/`
contain codes; generated text contains both. The extension does not mean encrypted.
|`.svg` |A vector image described in XML text. The generated SVG holds QR shapes
that stay sharp when scaled. It still exposes the encoded recovery payload.
|`.png` |A lossless pixel image. The workflow PNG is public documentation;
a generated backup PNG contains a QR of secret data.
|`.pdf` |A page document. The generated A4 PDF contains both a QR and readable
codes and instructions. Treat the file and every printed copy as secrets.
|`.ttf` |A TrueType font asset. The build embeds its bytes so the PDF renderer
does not need a font installed on the user's machine.
|`.gitignore` |Git's ignore rules. The leading dot makes this file hidden in many
file browsers. It has no ordinary extension and does not encrypt or restrict access.
|===

On Linux the built executable is usually `cli/target/release/mfa-backup`, with no
extension. Run that program, not an individual `.rs` file.
The extension is a naming convention, not proof that a file is safe or valid.

== Code, Metadata, And Data

Code tells the program what to do: parse arguments, count bytes, read lines,
render images, and write files. That behavior lives in `cli/src/`.

Metadata describes the project. In `Cargo.toml`, `[package]` gives its name,
version, and Rust edition. `[dependencies]` declares the libraries it uses.
The edition selects Rust language rules; it is not a recovery-code version.
This manifest is not a runtime config file for the tag. `--tag` selects the tag.
Edit the manifest deliberately. Let Cargo update `Cargo.lock`; keep the lockfile
with this application so later builds resolve the same library versions.

Data is what the program processes: recovery codes and instructions.
It belongs in input and output files, not hard-coded into Rust source.
The tests use fictional data to check behavior without exposing real accounts.

The font is a build asset. Its license explains redistribution rights.
Keep both with the source. Keep the workflow PNG with its `.plantuml` source
because the README displays that image. Other interim renders need not be retained.

There is also metadata _inside_ file formats. An NDEF Text record has a status byte,
language bytes, and length fields around its text. Those bytes count toward tag
capacity. They are different from Cargo's project metadata.
The account context and recovery instructions are payload content, not harmless
build metadata. Never put passwords in them.

Git ignore rules keep new private and generated files out of normal Git staging.
They do not stop another program reading those files, remove already tracked files,
or prevent someone force-adding them. Review what you share.

== Reading Order

. link:../cli/src/main.rs[main.rs]: arguments, entry point, and the `run` recipe.
. link:../cli/src/payload.rs[payload.rs]: tag choices, text composition, and byte limits.
. link:../cli/src/input.rs[input.rs]: files, terminal input, EOF, and line rejection.
. link:../cli/src/output.rs[output.rs]: QR rendering and safe file creation.
. link:../cli/src/pdf.rs[pdf.rs]: units, text layout, and drawing the QR matrix.

Each module has one job. Its tests sit below its implementation.
`main.rs` connects the jobs; it does not contain their details.

== Follow One Run

`main` asks clap to parse the arguments into `Args`.
It calls `run` and prints an error if the operation fails.
A nonzero exit status tells the shell that no successful backup was produced.

`run` reads the codes. It either reads an instruction file or prompts for lines.
It combines and validates the text. Then it renders and saves the four outputs.
Only byte counts are printed, never the codes.

Stop at each `?`. Ask what can fail there and whether a file has been created yet.
Input and layout errors happen before file writing starts.

== Types Worth Knowing

* `String` owns UTF-8 text. `&str` borrows text without copying it.
* `PathBuf` owns a filesystem path. `&Path` borrows one.
* `Vec<u8>` owns bytes, such as an encoded PDF or PNG.
* `Option<PathBuf>` is either `Some(path)` or `None`. Here it selects file input or prompting.
* `Result<String, String>` is either `Ok(text)` or `Err(message)`.
* `usize` is used for byte counts and collection indexes.

The ampersand in `prepare(&codes, &instructions, args.tag)` borrows the strings.
The caller still owns them. The function returns a new owned payload.
`Tag` is a small enum with `Copy`, so passing it does not consume the caller's value.

`match` handles each alternative explicitly. Adding a new tag means updating the
enum and its capacity match. Rust checks that the match covers every variant.

== Errors Without Panics

.Propagate payload preparation errors
[source,rust]
----
let text = prepare(&codes, &instructions, args.tag)?;
----

If preparation succeeds, `text` receives the payload.
If it fails, `?` returns the error from `run` immediately.
The caller handles that error. There is no need to panic.

`map_err` changes an error into a short message suitable for the user.
The prompt loop uses `io::Result` because its fallible operations are reads and writes.
Its caller converts I/O errors and performs the final payload check.

Tests use `unwrap` when success is expected. If that expectation is wrong, the test
fails. That is different from using `unwrap` for normal user input in the program.

== Bytes And Boundaries

Rust strings use UTF-8. `len()` counts bytes; `chars().count()` counts Unicode
scalar values. Neither is a universal count of visible characters.
The NFC limit is a byte limit, so the payload rules use `len()`.

The text also needs an NDEF header and a Type 2 TLV envelope.
Those length fields grow at their boundaries. `ndef_size` is the single source
of that calculation. The prompt budget reuses it rather than copying its rules.

The prompt builds a candidate string before changing accepted instructions.
If the candidate is too large, `continue` starts the next iteration without
committing it. `break` leaves the loop at EOF or exact capacity.

== Testable Input

`impl BufRead` means any value that supports buffered reading.
`&mut impl Write` borrows a writable destination so the prompt can update it.
These are traits: contracts describing the operations a type provides.

In a real run, the values are locked standard input and standard error.
In tests, `Cursor` supplies text from memory and a byte vector captures feedback.
The same prompt code runs in both cases. No terminal automation or real codes
are needed to test the capacity rules.

== Output And Layout

The QR library creates one matrix. SVG, PNG, and PDF all use it.
The program does not invent its own QR encoding algorithm.
PDF constants include their units in their names. Font points are converted to
millimetres before calculating line height and text width.

All formats are rendered in memory before files are opened.
`create_new(true)` refuses to overwrite an existing path.
`#[cfg(unix)]` enables owner-only permissions on Unix systems.
If writing fails, cleanup removes only files created by that call.
This is best-effort cleanup, not a crash-proof transaction or secure erasure.
File permissions and Rust's memory safety do not encrypt the codes.

== Run The Tests

From the project root:

.Run all tests or only payload tests
[source,shell]
----
cargo test --manifest-path cli/Cargo.toml
cargo test --manifest-path cli/Cargo.toml payload::tests
----

`#[cfg(test)]` compiles the test modules only for a test build.
Each test sets up an input, performs an operation, and checks the result.
Start with the exact-capacity test. Compare a fitting payload with one extra byte.

== Small Exercises

. Add a prompt test with a blank line between instructions. Check its byte count.
. Add a test for another supported non-ASCII character. Count bytes, not glyphs.
. Add a NUL-input rejection test. Check that the rejected line is absent from the result.

Change one thing, predict the result, and run the focused test.
Do not experiment with the real codes or weaken the private-output checks.
