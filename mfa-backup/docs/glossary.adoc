A4:: A standard paper size of 210 by 297 millimetres.
adoc:: The usual filename extension for an AsciiDoc document; it is not a separate language.
API:: Application Programming Interface; the operations a library or service exposes to other code.
ASCII:: American Standard Code for Information Interchange; a 128-value character encoding covering English letters, digits, punctuation, and control characters.
AsciiDoc:: A plain-text markup language for writing structured documents with headings, links, lists, tables, and code examples.
Asciidoctor:: A tool that converts AsciiDoc documents into formats such as HTML; PDF support uses an additional converter.
Asset:: A supporting file used by the program, such as its embedded print font.
Attribute:: Rust syntax beginning with #[...] that supplies instructions to the compiler or tools, such as derive or test settings.
Authentication:: Checking that someone controls the credentials needed to access an account.
Authentication factor:: One category of evidence: something you know, something you have, or something you are.
Backup:: An additional copy or recovery method kept so that loss of the primary one does not prevent recovery.
Base64:: An encoding that represents bytes as printable text; it increases size and does not encrypt the content.
Binary file:: A file whose bytes are not intended to be read directly as plain text, such as a PNG, font, or executable.
Borrowing:: Giving Rust code access to a value through a reference without transferring ownership.
Build:: The process of compiling source code and combining it with dependencies to produce an executable.
Byte:: Eight bits; the unit used here to measure text storage and NFC capacity.
CAC:: Common Access Card; a DoD smart-card credential with protections that a plain NTAG215 backup does not provide.
Cargo:: Rust's package manager and build tool; it reads the manifest, resolves dependencies, builds the program, and runs tests.
Checksum:: A value calculated from data to help detect changes; it is not encryption and by itself does not prove who created the data.
clap:: The Rust library this CLI uses to parse arguments and generate help text.
CLI:: Command-Line Interface; a program used through commands and text in a terminal.
Clipboard:: Temporary storage used for copied text or images; recovery codes placed there can become another exposed copy.
Code:: Instructions that define a program's behavior; in the phrase recovery code, code instead means a secret value.
Compiler:: A tool that translates source code into executable machine instructions and checks language rules.
Crate:: A Rust compilation unit, such as a library or binary; a Cargo package can contain more than one crate.
Ctrl-C:: A terminal key combination that normally interrupts a running program; during this CLI's prompt it cancels input.
Ctrl-D:: A Unix terminal key combination that signals the end of input on an empty line; it is not a character stored in the payload.
Data:: Values that a program processes, such as instructions and recovery codes, rather than the program itself.
Dependency:: Another package or library that the program relies on.
DoD:: The US Department of Defense, which issues the CAC credentials used as a security comparison in the README.
DRY:: Don't Repeat Yourself; keep a shared rule in one place instead of maintaining several copies.
Encoding:: Representing data in a particular form so it can be stored or transferred; encoding is not secrecy.
Encryption:: Protecting data with a cryptographic key so that it cannot normally be read without the corresponding decryption secret.
Enum:: A Rust type with a fixed set of named alternatives, such as the supported NFC tag types.
EOF:: End Of File; a reader's signal that no more input is available, including completion of terminal input.
Error propagation:: Passing an error back to a caller; Rust's question-mark operator performs this early return for a failing Result.
Executable:: A built program that the operating system can run; on Linux it need not have a filename extension.
Exit status:: A number returned when a process ends; zero normally means success and nonzero signals failure.
File extension:: A suffix such as .rs or .pdf that conventionally identifies a file's format; it is not proof of validity or safety.
FIPS:: Federal Information Processing Standards; referencing these standards does not certify this project or its tag.
Font:: Data describing how characters are drawn; this project embeds a monospaced font in its PDFs.
Git:: A version-control tool that records changes to project files.
Gitignore:: Rules in a .gitignore file that keep matching untracked files out of normal Git staging; they do not encrypt files or remove tracked copies.
Hash:: A one-way value derived from data; storing only a hash of recovery codes would not preserve the original codes for recovery.
HTML:: HyperText Markup Language; a format that structures web pages and rendered documentation.
I/O:: Input and output, such as reading terminal text or writing a file.
Include directive:: An AsciiDoc instruction that inserts another document's content during rendering; the README includes this glossary that way.
KISS:: Keep the design simple; here it means line-by-line feedback instead of a live terminal editor.
Library:: Reusable code called by a program, such as the QR or PDF library.
Lockfile:: Cargo.lock, the generated record of resolved dependency versions and checksums; it does not lock files or the NFC card.
Macro:: A Rust construct that generates code during compilation; include_bytes! embeds a file's bytes into the built program.
Manifest:: Cargo.toml, the TOML file describing the Rust package and its build dependencies.
Metadata:: Information describing something else, such as a package version or an NDEF record length; the recovery codes themselves are payload data.
MFA:: Multi-Factor Authentication; authentication using at least two different factor categories.
Module:: A named part of a Rust program that groups related code; this project gives each module one responsibility.
Monospaced:: A font style with a fixed character advance, useful for aligning codes and estimating line width.
NDEF:: NFC Data Exchange Format; the record format that NFC Tools uses to put the payload text on the tag.
NFC:: Near-Field Communication; short-range radio communication used to read and write the tag, not encryption.
NIST:: The US National Institute of Standards and Technology; it publishes the digital identity guidance referenced in the README.
NTAG215:: The NFC tag targeted by this project, with 504 bytes of user memory and optional password access protection, not payload encryption.
Octal:: Base-eight notation used for Unix permissions; 0600 permits owner read/write and 0700 also permits owner directory access.
Option:: A Rust type representing a value that is present with Some or absent with None.
Ownership:: Rust's rules for which binding owns a value and when its memory is released.
Package:: A Cargo project defined by a manifest, containing source code and one or more build targets.
Passphrase:: A secret made from words or other text; it can serve as a password or an encryption secret.
Password:: A secret used to authenticate or unlock something; keep the login password out of the recovery-code backup.
Payload:: The actual text being backed up: context, instructions, and recovery codes, before format headers are added.
PDF:: Portable Document Format; a fixed-page document format used here for the A4 QR-and-text printout.
Permission:: An operating-system access rule for a file or directory; permissions are not encryption.
Phishing:: Tricking someone into disclosing credentials or using a counterfeit login service.
PIN:: Personal Identification Number; a numeric access secret whose protection depends on the device, not merely on calling it a PIN.
Plaintext:: Data that can be read without decryption, even when represented as a QR or stored in an image file.
PlantUML:: A language and rendering tool for describing diagrams in text; the .plantuml file documents the workflow.
PNG:: Portable Network Graphics; a lossless pixel-image format used for phone QR images and the workflow illustration.
Point:: A typographic unit equal to one seventy-second of an inch; PDF font sizes use points rather than millimetres.
Print queue:: Pending print-job data, which can retain a copy of the recovery-code page.
QR:: Quick Response code; a two-dimensional barcode containing data that a scanner can decode, not an encryption method.
Quiet zone:: The blank border around a QR that helps a scanner distinguish it from surrounding marks.
Read protection:: A tag setting requiring an access secret before reading protected memory; protecting only writes does not hide the codes.
Recovery code:: A service-issued secret, usually usable once, that helps regain access when the normal authentication method is unavailable.
Reference:: A Rust value that points to borrowed data, written with an ampersand in types such as &str.
Rendering:: Turning a description into an image or document, such as PlantUML into PNG or AsciiDoc into HTML.
Result:: A Rust type representing either success with Ok or failure with Err.
RF shielding:: Material that reduces radio-frequency communication through the holder; it does not encrypt the tag or protect an exposed QR.
Rust:: A compiled programming language whose ownership and type rules help prevent many memory-safety errors; it does not automatically secure the data handled by a program.
Secure erasure:: Making stored data unrecoverable using an appropriate sanitization method; ordinary file deletion is not a guarantee of this.
Source code:: Human-readable program instructions, stored here in .rs files before compilation.
Struct:: A Rust type that groups named fields, such as the CLI's argument values.
SVG:: Scalable Vector Graphics; an XML-based image format whose shapes remain sharp when scaled, used here for laser and print QR artwork.
Terminal:: A text interface to a shell and running programs.
Test:: Code that exercises behavior and checks expected results; this project's tests use synthetic codes.
TLV:: Type, Length, Value; the envelope around the NDEF message in a Type 2 NFC tag, whose bytes also consume storage.
TOML:: Tom's Obvious Minimal Language; a structured configuration format used by Cargo.toml.
Trait:: A Rust contract describing operations that a type provides, such as buffered reading or writing.
TTF:: TrueType Font; the format of the embedded font asset.
Unicode:: A standard assigning codes to characters from many writing systems; one visible character can involve several Unicode scalar values.
UTF-8:: A byte encoding of Unicode; ASCII characters use one byte, while other characters can use several.
Vector image:: An image represented by shapes rather than a fixed grid of pixels, such as an SVG QR.
XML:: Extensible Markup Language; a structured text format used to describe SVG elements.
