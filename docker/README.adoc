Every container definition lives under `docker/`. Explicit candidate updates block HIGH and CRITICAL findings by default; `--allow-findings` records a compact CSV summary and Dockerfile in that image's README before promotion. Image-specific exceptions are described in their README. Trivy needs database access on the first scan; see `docker-trivy/README.adoc` for manual reports.

The Pi runs a prebuilt ARMv6 image. Compose does not build it.

.Start the preloaded Rust service on the Pi
[source,bash]
----
cd docker/docker-wainlux-rs
docker compose up -d
----

The service uses `/dev/ttyUSB0` and port `8081`.

[WARNING]
====
All tool containers use **local Dockerfiles** with **digest-pinned base images**. Scripts and Compose files use those local images, never a mutable remote tag.

A digest identifies the exact base image. Lockfiles and checksums pin application dependencies and downloaded tools. The image inventory records these inputs. Candidate images are scanned before promotion; a failed scan leaves the previous local image selected.

See <<adr-029-container-security,ADR-029: Local Container Builds for Supply Chain Security>> for the full rationale.
====
